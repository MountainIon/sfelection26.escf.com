# sfelection26.escf.com

Side-by-side endorsements from San Francisco organizations for the November 3, 2026 election, with broad-consensus candidates and measures highlighted.

The page is one self-contained file, `site/index.html`, generated by `scripts/build.py`.

## How updates work

1. Every 6 hours, the **Update endorsement data** workflow pulls the latest data from [sfendorsements.com](https://sfendorsements.com/) and [OpenBallot](https://www.openballot.app/elections/california-general-election-2026/compare), merges it, and applies `data/overrides.json`.
2. If anything changed, it opens a pull request (or updates the open one) on `auto/data-update`. The PR description lists every position that changed, any new organizations, conflicts between sources, and overrides the sources have caught up with.
3. Review and merge. Merging to `main` runs **Deploy site**, which publishes `site/` to GitHub Pages.

If a source changes its page layout or the data looks broken, the build stops instead of opening a PR, and the workflow run fails. GitHub emails you about failed scheduled runs. If total positions drop by more than 10%, the PR opens with a warning at the top.

Precedence for each cell: `data/overrides.json` > OpenBallot > sfendorsements.com.

## Files

| Path | What it is |
|---|---|
| `data/orgs.json` | Organizations (columns): display name, names on each source, bloc (`prog`, `mod`, `civic`, `gop`), `featured` (tinted, shown first), optional `url` override, `no_logo`. New organizations found on either source are added automatically; to keep one permanently or change its bloc, add it here. Individuals and explainer-only guides on OpenBallot go in `exclude_openballot`. |
| `data/races.json` | Rows: label, section, description, and the matching name on each source. |
| `data/overrides.json` | Hand corrections (with the source URL) for positions the aggregators don't have yet, name spellings, and the notice under the heading. |
| `data/snapshot.json` | The merged data from the last build. Diffs of this file show exactly what changed. |
| `template/page.html` | Page layout, styles and scripts. |
| `assets/logos/` | Cached organization logos (from OpenBallot), embedded into the page at build time. |
| `scripts/build.py` | The build. |

## Common tasks

Correct a position: add an entry to `data/overrides.json` on `main`, then run the update workflow (Actions tab → Update endorsement data → Run workflow). Don't edit the `auto/data-update` branch; each run regenerates it.

Change the layout or wording: edit `template/page.html`, then rebuild locally with `--force` (template changes alone don't change the data snapshot):

```bash
python3 scripts/build.py --force
```

Rebuild from the last downloads without fetching again:

```bash
python3 scripts/build.py --offline --force
```

## One-time setup

1. Create an empty GitHub repository, then push this folder to it (see below).
2. **Settings → Pages**: set Source to **GitHub Actions**. Under Custom domain, enter `sfelection26.escf.com` and save; tick **Enforce HTTPS** once the certificate is issued.
3. **Settings → Actions → General → Workflow permissions**: choose **Read and write permissions** and tick **Allow GitHub Actions to create and approve pull requests**.
4. At your DNS provider for `escf.com`, add a `CNAME` record: name `sfelection26`, value `<your-github-username>.github.io`.
5. Run **Deploy site** once from the Actions tab to publish the current page.

Optional: verify `escf.com` under your GitHub account settings (Pages → Verified domains) to prevent anyone else from claiming the subdomain.
